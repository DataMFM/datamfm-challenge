Submission Guidelines

Before Uploading

Select the correct Task in the submission metadata. Dev Phase and Test Phase are dataset splits; they do not select the task. The selected Task controls which evaluator runs on your uploaded .zip.

A small format-only example package with partial ground-truth snippets and matching prediction files is available at submission_format_examples. These examples are for inspecting the expected structure and fields; they are not complete EvalAI submissions.

Document Parsing Format

For Document Parsing, submit a .zip archive containing one Markdown file per document. The archive should be flat, and each filename must match the corresponding document UUID in the ground truth.

submission.zip
├── 00000000-0000-0000-0000-000000000001.md
├── 00000000-0000-0000-0000-000000000002.md
└── ...

Do not wrap the Markdown files inside an extra top-level directory. Submissions with missing or extra filenames will fail validation.

Document Markdown Rules

  • Text: Use standard Markdown. Paragraphs should be separated by blank lines.
  • Formulas: Use LaTeX notation. Display formulas should use $$...$$, and inline formulas should use $...$.
  • Tables: HTML <table> format is recommended because it supports merged cells. Markdown pipe tables are also accepted.
  • Reading order: Elements should appear in natural reading order within each document-level .md file.

Chart Understanding Format

For Chart Understanding, submit a .zip archive containing JSONL prediction files for both real and synthetic chart splits.

submission.zip
├── real/
│   ├── chart2csv_predictions.jsonl
│   └── chart2summary_predictions.jsonl
└── synthetic/
    ├── chart2csv_predictions.jsonl
    └── chart2summary_predictions.jsonl

Use newline-delimited JSON (.jsonl), with exactly one JSON object per line. Do not upload a single JSON array for Chart Understanding predictions. Each JSONL row must include an image identifier such as imagename, image_name, filename, or id. CSV prediction rows should use predicted_csv, and summary prediction rows should use predicted_summary. The worker also accepts prediction, output, csv, or summary for compatibility, but the explicit field names are recommended.

Submission Metadata

Every submission must include:

  • Task: Document Parsing or Chart Understanding. Choosing the wrong task for your uploaded file format will cause evaluation to fail.
  • ModelName: Name of your model, such as MinerU, Nougat, or GPT-4o.
  • ModelType: End-to-End VLM, Pipeline, Hybrid, or Other.
  • ExternalData: Whether external training data beyond the provided dataset was used.

Leaderboard Notes

The EvalAI leaderboard contains both Document Parsing and Chart Understanding columns. For each submission, only the columns for the selected Task are meaningful; the other task's columns are placeholders. The shared Overall column is the overall score for the selected task.

Limits

  • Dev Phase: 5 submissions/day, 50/month.
  • Test Phase: 2 submissions/day, 10/month.

Evaluation Details

Submissions are routed by the required Task metadata. Dev Phase and Test Phase select the evaluation split, while Task selects the evaluator. All final scores reported as percentages use the range 0-100, where higher is better unless explicitly noted.

Document Parsing Evaluation

Document Parsing follows the OmniDocBench md2md evaluation pipeline. Submitted document-level Markdown files are parsed into text blocks, formulas, tables, and reading-order sequences. The evaluator then uses quick matching to align predicted elements with ground-truth elements before computing the metrics below.

Metric Definition Range and Direction
Text ED Normalized Levenshtein edit distance between matched predicted and ground-truth text blocks. For a matched pair (p, g), ED(p, g) = Levenshtein(p, g) / max(|p|, |g|). The leaderboard reports the average edit distance across matched text blocks and pages. 0-1, lower is better. 0 means an exact text match.
Table TEDS Tree Edit Distance-based Similarity between matched predicted and ground-truth table HTML trees. It evaluates both table structure and cell content after parsing tables into comparable tree representations. 0-100, higher is better. 100 means the table tree and content match perfectly.
Formula CDM Character Detection Matching for matched display formulas. Predicted and ground-truth LaTeX formulas are rendered, characters are detected and matched spatially, and the reported score is the CDM F1 score: CDM = 2 * Precision * Recall / (Precision + Recall). 0-100, higher is better. Equivalent LaTeX renderings can receive high scores even when their source strings differ.
Reading Order Reading-order quality is computed from normalized edit distance over the predicted and ground-truth element order sequences. The reported score converts distance to a high-is-better score: Reading_Order = (1 - Reading_Order_ED) * 100. 0-100, higher is better. 100 means the predicted element order matches the ground truth.

The Document Parsing overall score averages the four normalized high-is-better components:

Document_Overall =
  ((1 - Text_ED) * 100 + Table_TEDS + Formula_CDM + Reading_Order) / 4

Chart Understanding Evaluation

Chart Understanding evaluates JSONL predictions for chart-to-CSV and chart-to-summary tasks over both real and synthetic chart splits. Each prediction row is matched to a ground-truth row by image identifier, using fields such as imagename, image_name, filename, or id.

Metric Definition Range and Direction
CSV Numeric F1 All numeric values are extracted from the predicted CSV and reference CSV. A predicted number matches a reference number if |pred - gt| <= max(1e-4, 0.01 * |gt|). Matches are one-to-one. Precision, recall, and F1 are computed from matched numeric values. 0-100, higher is better.
CSV Structural Score CSV structure is scored by comparing row count, column count, and header overlap. The score is (RowScore + ColumnScore + HeaderScore) / 3, where row and column scores are min/max ratios and header score is Jaccard overlap over normalized header cells. 0-100, higher is better.
Summary ROUGE-L Predicted chart summaries are compared with reference summaries using ROUGE-L F1. Tokens are lowercased alphanumeric spans, and the longest common subsequence determines precision and recall. 0-100, higher is better.
Summary Numeric Fact F1 Numeric values are extracted from predicted and reference summaries and matched with the same tolerance rule used for CSV Numeric F1. The final score is numeric precision/recall F1. 0-100, higher is better.

The Chart Understanding overall score averages the four chart metrics:

Chart_Overall =
  (CSV_Numeric_F1 + CSV_Structural_Score + Summary_ROUGE_L + Summary_Numeric_Fact_F1) / 4

Result Storage and Auditability

For both tasks, the remote worker saves the uploaded archive, extracted predictions, raw metric files, final scores, and request metadata for each submission. These artifacts are used to audit submissions and maintain the external Chart Understanding leaderboard.
